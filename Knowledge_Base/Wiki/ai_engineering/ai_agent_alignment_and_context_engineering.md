## 📌 1. ทำไม AI ถึง "ดื้อ / ลืม / ไม่ทำตามกฎ" (The 3 Core Failure Modes)

จากงานวิจัยด้าน LLM Agent Architecture ปี 2026 พบว่าปัญหาที่ AI ไม่ทำตามกฎไม่ได้เกิดจากโมเดลไม่ฉลาด แต่เกิดจาก **3 ปรากฏการณ์ทางวิศวกรรม**:

```text
[ Context Window ]
┌───────────────────────────┐
│ 1. System Prompt (กฎเริ่มต้น) │ ➔ จำได้ดี (High Attention)
├───────────────────────────┤
│ 2. "Lost in the Middle"   │ ➔ จุดบอด! กฎและบริบทส่วนนี้จะ "จมหาย"
│    (ประวัติแชท, ผลลัพธ์ Tool)  │    เมื่อ Context ยาวเกิน 20,000+ Tokens
├───────────────────────────┤
│ 3. ท้าย Prompt (คำสั่งล่าสุด)  │ ➔ จำได้ดี (Recency Bias)
└───────────────────────────┘
```

1. **The "Lost in the Middle" U-Curve:**  
   * โมเดลจะจำข้อความที่อยู่ **หัว** และ **ท้าย** ของ Context ได้ดีที่สุด แต่ข้อมูลที่อยู่ **ตรงกลาง** (ประวัติแชทที่คุยกันยาวๆ หรือก้อนผลลัพธ์จาก Tool) จะถูกลดทอนความสนใจ (Attention Saturation) ทำให้กฎสำคัญที่เคยตกลงกันไว้หลุดลอยไป
2. **The "Instruction Novel" Anti-Pattern (กฎยาวจนหูหนวก):**  
   * ยิ่งเราเขียนกฎยาวขึ้นเรื่อยๆ เพื่อดักทุก Edge Case โมเดลจะเกิดภาวะ **Instruction Attenuation (กฎหักล้างกันเองและน้ำหนักของแต่ละกฎเจือจางลง)**
3. **Conformity Bias & Error Compounding:**  
   * AI มักจะชอบ "เออออห่อหมก" หรือเดาข้อมูลเพื่อทำให้ประโยคสนทนาลื่นไหล (Hallucination เพื่อเอาใจ) มากกว่าการหยุดตรวจ Fact จริง

## 🛠️ 2. วิธีการแก้ปัญหาเชิงสถาปัตยกรรม (2026 Modern Solutions)

วงการ AI ปี 2026 ได้เปลี่ยนผ่านจาก "Prompt Engineering" (การแก้คำสั่ง) มาเป็น **"Harness & Context Engineering" (การจัดระบบท่อส่งข้อมูล)** ดังนี้:

### ✅ 1. กฎ Context Compression & Anchoring (การปักหมุดข้อจำกัด)
* **อย่าปล่อยให้กฎสำคัญจม:** กฎเหล็กสูงสุด (Hard Constraints เช่น *ห้ามเดาข้อมูล, ต้องค้นหาก่อนตอบ, ไม่เยินยอ*) ต้องถูกนำมาปักหมุดไว้ใน System Prompt สั้นๆ เสมอ (เหมือนที่เราแก้ใน `GEMINI.md` เหลือ 5 ข้อ)

### ✅ 2. Progressive Disclosure (โหลดกฎเมื่อจะใช้เท่านั้น)
* กฎเฉพาะทาง (การลงทุน, QA, Frontend) ต้องแยกเป็น **Modular Rules (`.agents/rules/`)** และโหลดขึ้นมาเฉพาะเมื่อ Agent เข้าไปแตะไฟล์ในหมวดหมู่นั้นๆ เพื่อไม่ให้กินพื้นที่สมองโดยเปล่าประโยชน์

### ✅ 3. Subagent Memory Isolation (แยกห้องทำงานเพื่อความแม่นยำ)
* เมื่องานมีความซับซ้อนและใช้ข้อมูลเยอะ (เช่น การสแกนงบ 10-K หรือรัน Browser Testing) **ต้องโยนให้ Subagent (เช่น Hermes หรือ Research Subagent) รันใน Workspace แยก** แล้วส่งกลับมาเฉพาะ "ข้อสรุปสุดท้าย" เพื่อไม่ให้ Context Window หลักของมอลิปนเปื้อน

## 🎯 3. การนำมาใช้จริงกับระบบของบอส (Direct Implementation)

1. **Malli's Rule:** มอลิจะรักษาความยาวของ `GEMINI.md` ให้กระชับ สั้น และทรงพลังตลอดไป
2. **Action-First Routine:** เมื่อมีบทเรียนใหม่ มอลิจะรีบแปลงเป็นโค้ด/สคริปต์ หรือบันทึกเข้า Obsidian Vault ทันทีเพื่อสร้าง Persistent Memory
3. **Subagent Delegation:** งานค้นหาเอกสารยาวๆ จะใช้ Subagent จัดการแยก เพื่อรักษาความคมและสมาธิในห้องแชทหลักกับบอสค่ะ
